The Plan: "Auth & Capture" Flow
1. Database (models.py)
We need to store the specific Kashier Transaction ID.

Why? When you create an order, you get an Order ID (e.g., your UUID). But when the customer pays, Kashier generates a Transaction ID (e.g., TX-12345).

To Void or Capture a payment later, Kashier's API requires that specific TX-12345 ID.

Action: Add kashier_transaction_id field to the Transaction model.

2. The Workers (utils.py)
You currently have place_sickw_order. You are missing the tools to actually talk to Kashier's backend for the advanced stuff.

Action: Add get_kashier_fep_url() (Helper for Test vs Live URLs).

Action: Add capture_payment(transaction) (Sends "Give me the money" command).

Action: Add void_payment(transaction) (Sends "Release the money" command).

3. The Trigger (serializers.py & views.py - Create)
Action: Ensure the creation logic sets the status to PENDING.

Action: Ensure the create view does not capture money immediately. (Note: You usually configure "Pre-Authorization" as the default in your Kashier Dashboard settings, so the code just initiates a standard session).

4. The Brain (views.py - Webhook)
This is where the magic happens. We need to rewrite the webhook to be smarter.

Current: Success -> Mark Completed -> Sync Sickw.

New Logic:

Receive Webhook -> Save TX-ID.

Mark AUTHORIZED (Money Held).

Run place_sickw_order(transaction).

IF True (Good IMEI): Call capture_payment -> Mark COMPLETED.

IF False (Bad IMEI): Call void_payment -> Mark VOIDED.
